## [4] 오늘 협업 중 제안하거나 피드백한 내용

다른 팀원이 공유해 주신 베이스라인 학습 결과(검증 mAP 0.98)의 학습 설정 파일(`args.yaml`)을 확인하던 중 한 가지 문제를 발견했습니다. 여기서 mAP(mean Average Precision)는 객체 탐지에서 모델 성능을 종합적으로 보여 주는 지표입니다.

`augment=False` 옵션이 학습 단계에서는 실질적으로 동작하지 않고, 추론(predict) 단계에서 TTA(Test-Time Augmentation, 추론 시 이미지를 여러 번 변형해 결과를 합치는 기법)용으로만 작동한다는 사실을 확인했습니다. 즉, `augment=False`를 줘도 학습 시에는 ultralytics 기본 증강(`mosaic 1.0`, 좌우 반전 `fliplr 0.5`, 확대·축소 `scale 0.5`, 평행 이동 `translate 0.1`, HSV 색 변형 기본값 등)이 그대로 적용되고 있었습니다.

이 상태에서는 각자 맡은 증강 기법을 기본값 강도로 추가해도, 이미 적용된 값을 다시 지정하는 꼴이 됩니다. 결과적으로 실험 자체가 성립하지 않는다는 점을 팀에 공유드렸고, 모든 증강 파라미터를 명시적으로 0으로 지정한 "진짜 bare 베이스라인"(아무 증강도 켜지 않은 순수 베이스라인)부터 다시 잡고 시작하자고 제안드렸습니다. 팀 동의를 얻었습니다.

## [5] 오늘 분석/실험 중 얻은 인사이트나 발견한 문제점

오늘 정리된 점입니다.

- ultralytics의 `augment` 플래그 동작 방식: 학습 단계에서 증강이 켜지는지는 `augment` 플래그가 아니라 각 하이퍼파라미터(`mosaic`, `fliplr`, `scale` 등) 값으로 결정됩니다. 0이 아닌 값이 하나라도 있으면 그 증강은 활성화됩니다. 팀원 누구도 이 점을 인지하지 못한 상태에서 실험 설계가 진행되고 있었습니다.
- 검증 점수 신뢰도 문제가 다시 확인되었습니다. 증강을 모두 꺼 보면 검증 mAP가 오히려 더 올라갈 가능성이 있습니다. 만약 그렇다면, 학습/검증 셋이 거의 동일한 분포(near-duplicate)라서 모델이 학습 이미지를 외우는 방식으로 검증을 맞히고 있다는 가설이 강화됩니다.
- 결론적으로 검증 점수만으로는 모델의 실제 성능을 평가할 수 없고, 캐글 테스트 셋 제출로만 검증이 가능한 상태입니다.

## [6] 일정 지연이나 협업 중 어려웠던 점

- 캐글 데이터셋 업로드 과정에서 Windows 환경 이슈가 몇 건 있었습니다. PowerShell의 `Compress-Archive`는 압축 속도가 너무 느려, 7-Zip을 별도로 설치해 해결했습니다.
- `Set-Content -Encoding UTF8`이 파일 앞에 BOM(Byte Order Mark, 인코딩 표시용 특수 바이트)을 붙여 버리면서, 캐글 CLI가 metadata를 cp949(한글 윈도우 기본 인코딩)로 잘못 해석하는 문제가 발생했습니다. `[System.IO.File]::WriteAllText`로 BOM 없이 저장해 해결했습니다.
- 이런 환경 이슈가 학습의 연결고리를 자주 끊는 형태로 작용했습니다. 팀원 온보딩용으로 해결법을 문서화해 둘 필요가 있어 보입니다.
