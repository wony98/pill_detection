## [4] 오늘 협업 중 제안하거나 피드백한 내용

팀 메신저에 두 가지 제안을 드렸습니다.

- `dl_idx` 한 가지 키로만 병합하면, 같은 약품이라도 출처(캐글 / AI Hub)에 따라 ID가 달라 두 행으로 분리될 위험이 있다는 점을 짚었습니다. 대신 `img_dl_name + mapping_code + drug_N` 3중 키 기준으로 병합하자고 제안드렸고, 시각화 자료(`cell16e_dl_idx_pattern.png`)로 공통 약품 54종 모두 +1 패턴이 일관된다는 점을 함께 공유드렸습니다.
- 베이스라인 입력 해상도를 640이 아닌 1024 이상으로 올려 잡자고 제안드렸습니다. 각인 글자가 작은 약품(예: 리피로우정 20mg)은 640 해상도에서는 모델이 글자 자체를 볼 수가 없다는 육안 검증 결과가 근거입니다.

## [5] 오늘 분석/실험 중 얻은 인사이트나 발견한 문제점

오늘 정리된 점입니다.

- 이슈 K(테스트 셋 배경 분포 차이) 가설은 기각되었습니다. 셀 14에서 테스트 이미지를 직접 들여다보니 학습 이미지와 같은 배경 분포로 나타났고, "테스트 셋은 배경이 다를 것"이라는 사전 우려는 해소되었습니다.
- AI Hub의 `cat_name` 필드는 상당수가 비어 있거나, `dl_idx`로부터 자동 생성된 값이라 학습 타겟으로는 부적합했습니다. 클래스 라벨로 신뢰할 수 있는 필드는 `img_dl_name` 하나로 좁혀집니다.
- 이슈 N(한 이미지 안에 객체가 4개를 초과해 잡힌 90건) 중 89건이 이슈 C(중복 annotation) 정리 단계에서 자동으로 해소되는 것을 확인했습니다. 별도 처리는 불필요합니다.
- 참조 CSV와의 +57건 차이가 이슈 A(bbox 경계 위반) 57건과 정확히 일치한다는 점이 확인되었고, 팀장님 필터링 기준과 제 기준이 어떤 관계에 있는지가 명확해졌습니다.
- 외형이 같은 그룹(예: 원형 + 하양 20종)은 각인 / 색조 / 질감 차이로 구분이 가능하지만, 640 해상도에서는 각인이 소실되어 분류 실패 가능성이 높다는 점을 다시 확인했습니다.
