## 상세

### A. bbox 이미지 범위 초과 — 1건 · **치명**
- **증상**: 한 어노테이션에서 `bbox_x=6567`, 이미지 너비 `img_w=976`의 6.7배
- **영향**: 학습 시 좌표 클리핑 없으면 NaN/loss 폭주 위험
- **논의 포인트**:
  - 원본 JSON 오류인지, 좌표계 변환 실수인지 확인
  - 단순 제외 vs 수작업 복구
- **결정사항**:

### B. area_meta ≠ w×h — 6건 · 낮음
- **증상**: JSON의 `area` 필드 값이 `bbox_width × bbox_height`와 불일치
- **영향**: 실제 bbox는 정상, `area` 메타만 오차. COCO 평가 시 `area`는 small/medium/large 구분용이라 영향 적음
- **논의 포인트**:
  - 무시 or 재계산하여 덮어쓰기
- **결정사항**:

### C. 동일 좌표 이중 라벨링 (IoU=1.0) — 3쌍 · 중
- **증상**: 같은 이미지 내 bbox 2개가 완전히 동일한 좌표 (IoU=1.0), 부분 overlap은 0건
- **영향**: 중복 학습 → 해당 클래스 편향 / NMS 튜닝 무관
- **논의 포인트**:
  - 3쌍 수작업 검수 — 진짜 동일 약 2개인지, 중복 라벨링 오류인지
  - 2/3이 id=3351 일양하이트린정 2mg 집중 (D와 연관)
- **결정사항**:

### D. 누락 어노테이션 — 8건 · **높음**
- **증상**: 이미지-JSON 교차검증(3경로)에서 어노테이션 누락 감지. id=3351 일양하이트린정 2mg에 4건 집중
- **영향**: 학습 시 FN 유도 → recall 저하
- **논의 포인트**:
  - id=3351 전수 재검토 필요 (C 2/3 + D 4건 + F 4건 모두 이 클래스 집중)
  - 원본 JSON 복구 vs 해당 이미지 제외
- **결정사항**:

### F. 파일명 pos 2='1' 이상 — 4건 · 중
- **증상**: 파일명 두번째 위치 토큰이 '1'인 케이스 (다른 파일은 '0') — 전부 K-003351 조합

- **논의 포인트**:

## 참고: 주요 발견

- 232 이미지, 56 클래스, 763 어노테이션, 해상도 976×1280 단일 (train 기준)
- 클래스 불균형 51배: 일양하이트린정 2mg 153건 / 하위 10개 클래스 모두 3건

- category_id ↔ name 완전 1:1 (COCO 병합 안전)

- test_images 842장 내용은 미확인 (Cell 23에서 처리 예정)
